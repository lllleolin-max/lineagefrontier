# Model, subset and boundaries

Sources verified 2026-10-03: [in-toto Statement v1](https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md), [SLSA v1.2 build provenance](https://slsa.dev/spec/v1.2/build-provenance), [SLSA artifact verification](https://slsa.dev/spec/v1.2/verifying-artifacts), [GNU Make prerequisites](https://www.gnu.org/software/make/manual/html_node/Prerequisite-Types.html). Established provenance formats already describe outputs and resolved dependencies; Make already handles normal prerequisites and rebuilding. We claim a reproducible engineering combination, not a new provenance format or first dependency invalidation algorithm. The benchmark implements disclosed baselines, not full competitor tools.

## Manifest v1

`schema_version: 1`, `artifacts`, `statements`, `actions` are required. JSON input rejects duplicate keys, nonfinite constants and excessive nesting with an actionable error; reads are bounded to 2 MiB. Boolean true is not schema version 1. Optional provenance null/missing fields mean empty, but wrong-typed false/empty strings/objects are rejected. Inventory artifacts have portable unique `id`, SHA-256 `digest`, relative POSIX-style `path`, `kind: input|output`. One logical slot per recorded digest; duplicate bytes across different slots are rejected because bare digests do not disambiguate which mutable locator a historical dependency meant. Combine such aliases before import. Filenames and statement subject names are ignored for content resolution.

Raw statements use `_type: https://in-toto.io/Statement/v1` and `predicateType: https://slsa.dev/provenance/v1`. This URI remains constant across SLSA minor versions. Each subject and resolved dependency must contain SHA-256. Output subjects may be batched; their recorded prerequisites are identical in that statement. Require buildDefinition/buildType, object externalParameters (missing/null/empty means empty), runDetails/builder/id. Unrecognized standard/extension fields are ignored; additional digest algorithms may accompany SHA-256 but are not checked. No v0.2 import, DSSE unpacking, signature checks, embedded content verification, gitCommit-only dependencies, remote resolution or SLSA certification. All dependencies must resolve to inventory content. Input slots have no build provenance; every output slot has exactly one statement.

An action has portable `id`, sorted unique `inputs`/`outputs` referring to inventory slots, nonnegative integer `cost` <=10^12, and textual `instruction` for a reviewed external runner. Actions produce output slots only; inputs/outputs of one action are disjoint. Alternative actions may produce the same slot; atomic multi-output actions pay once. Catalog actions define future policy-approved recipes and need not reproduce historical dependency choices. Equivalence of different recipes is declared by the caller. An action consumes all inputs and guarantees all outputs only under the report's explicit execution condition. The planner never executes instructions, rewrites files or predicts new output digests.

## Invalidation and planning

1. Validate the recorded digest graph, topologically order it with deterministic ID tie breaking.
2. Stream actual local file SHA-256. Any changed/missing file or explicit recorded-version revocation seeds a cause. Propagate causes to historical descendants with deterministic shortest then lexicographic witness paths. An unrelated branch has no cause.
3. Current non-revoked source files are available, including a changed source's new version. Historical outputs are available only when byte-matching and with no cause. Revoked/missing inputs are unavailable; recorded-version output revocations may be replaced through a reviewed recipe.
4. Backward-close all candidate producers of requested unavailable slots, including initially valid prerequisites that any candidate batch could invalidate. For each selected subset, remove its produced slots and all historical descendants from initial reuse. Each slot has at most one producer in a supported plan; subsets with overlapping producers are disallowed. Enumerate up to 18 relevant actions, check prerequisites and charge each atomic action once. Minimize `(total_cost, action_count, sorted_action_ids)`. Every feasible plan is replayed by a separate checker that independently excludes overwritten generations.
5. Above the bound, conservative unique-producer greedy scheduling followed by reverse deletion returns a checked feasible upper bound with `optimality=UNKNOWN`. A bounded failure returns `status=UNKNOWN`, not an infeasibility proof. Old recorded descendants of a co-output cannot be mixed with its new generation. The same snapshot generation is consumed throughout. Historical provenance cycles are always invalid; unseeded catalog cycles find no feasible supported plan.

The ready frontier is the first eligible actions, not the entire plan or a minimum graph cut. Rebuilding requires every `execution_order` action. `invalidated_by_plan` reports previously usable generations displaced by selected actions, `replaced_valid_outputs` reports overwritten valid co-outputs; other valid branches remain reused. For example, rebuilding a rejected model in a batch with still-valid metrics requires rebuilding their old chart before making a bundle. An alternative model-only action can preserve that chart. Revocation reasons are explicit user evidence, not discoveries made by the tool. Assess a stable snapshot and apply plans against that same snapshot; this is not a cross-process transactional filesystem view.

## Complexity and bounds

Let V<=1000 artifacts, E<=10000 provenance edges, C<=128 direct causes, A<=1000 catalog actions. Hashing streams O(total local bytes), O(1 MiB) buffer per file, <=64 MiB per file. Topology is O((V+E) log V). Cause propagation stores O(C*V*V) path elements in the worst long-chain case and O(C*E*V) copying work; bounds are deliberately conservative and users should partition large inventories. Relevant action closure is O(A^2 * edge count) in the simple fixed-point implementation. Exact selection has <=2^18 subsets with O(A*action-edge-count) scheduling per subset. Approximate reachability/deletion is polynomial and makes no minimum claim. Manifest input <=2 MiB. No concurrency, resource scheduling, deadlines, cache transport or semantic equivalence proof. Costs are catalog assumptions, not predictions of wall clock or money.

Tests include actual byte changes, revoked/absent sources, independent branches, import failures, permutations and a separate small action-order oracle. Oracle success validates only tested finite cases; no general theorem or external security audit is asserted.

## Snapshot association

Assessments contain a deterministic inventory/provenance fingerprint and a canonical report digest. `plan()` rejects another inventory/path/provenance revision and accidental report edits. JSON roundtrips preserve it; changing only action costs/recipes is allowed because those do not affect recorded byte assessment. This is integrity/association checking, not authentication: an adversary can recompute an unkeyed digest. A valid old snapshot does not automatically observe later filesystem writes; obtain a new assessment or run against an unchanged external snapshot.
